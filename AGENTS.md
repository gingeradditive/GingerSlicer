# Repository Guidelines

## Project Structure & Module Organization
OrcaSlicer’s C++17 sources live in `src/`, split by feature modules and platform adapters. User assets, icons, and printer presets are in `resources/`; translations stay in `localization/`. Tests sit in `tests/`, grouped by domain (`libslic3r/`, `sla_print/`, etc.) with fixtures under `tests/data/`. CMake helpers reside in `cmake/`, and longer references in `doc/` and `SoftFever_doc/`. Automation scripts belong in `scripts/` and `tools/`. Treat everything in `deps/` and `deps_src/` as vendored snapshots—do not modify without mirroring upstream tags.

## Build, Test, and Development Commands
Use out-of-source builds:
- `cmake -S . -B build -DCMAKE_BUILD_TYPE=Release` configures dependencies and generates build files (Visual Studio generator on Windows).
- `cmake --build build --target GingerSlicer --config Release --parallel 16` is the canonical Windows build command. Output: `build/src/Release/GingerSlicer.dll` (loaded by `GingerSlicer_app_gui.exe`). Resources are symlinked into the build tree automatically.
- `cmake --build build --target tests` then `ctest --test-dir build --output-on-failure` runs automated suites.
Platform helpers such as `build_linux.sh`, `build_release_macos.sh`, and `build_release_vs2022.bat` wrap the same flow with toolchain flags. Use `build_release_macos.sh -sx` when reproducing macOS build issues, and `scripts/DockerBuild.sh` for reproducible container builds. Dependencies are pre-built in `deps/build/OrcaSlicer_dep/` (do not regenerate unless `deps_src/` changed).

## Coding Style & Naming Conventions
`.clang-format` enforces 4-space indents, a 140-column limit, aligned initializers, and brace wrapping for classes and functions. Run `clang-format -i <file>` before committing; the CMake `clang-format` target is available when LLVM tools are on your PATH. Prefer `CamelCase` for classes, `snake_case` for functions and locals, and `SCREAMING_CASE` for constants, matching conventions in `src/`. Keep headers self-contained and align include order with the IWYU pragmas.

## Testing Guidelines
Unit tests rely on Catch2 (`tests/catch2/`). Name specs after the component under test—for example `tests/libslic3r/TestPlanarHole.cpp`—and tag long-running cases so `ctest -L fast` remains useful. Cover new algorithms with deterministic fixtures or sample G-code stored in `tests/data/`. Document manual printer validation or regression slicer checks in your PR when automated coverage is insufficient.

## Commit & Pull Request Guidelines
The history favors concise, sentence-style subject lines with optional issue references, e.g., `Fix grid lines origin for multiple plates (#10724)`. Squash fixups locally before opening a PR. Complete `.github/pull_request_template.md`, include reproduction steps or screenshots for UI changes, and mention impacted presets or translations. Link issues via `Closes #NNNN` when applicable, and call out dependency bumps or profile migrations for maintainer review.

## Security & Configuration Tips
Follow `SECURITY.md` for vulnerability reporting. Keep API tokens and printer credentials out of tracked configs; use `sandboxes/` for experimental settings. When touching third-party code in `deps_src/`, record the upstream commit or release in your PR description and run the relevant platform build script to confirm integration.

## Module Map (Ginger-specific)
Use this as a routing table before searching. Localize first, then read narrowly.

### Configuration & schema
- `src/libslic3r/PrintConfig.hpp` / `PrintConfig.cpp`: source of truth for every parameter. Definitions are macro-generated via `PRINT_CONFIG_CLASS_DERIVED_*`. Adding a parameter requires touching both files (declaration + `ConfigOptionDef` with label/tooltip/range/mode).
- `src/libslic3r/Config.hpp` / `Config.cpp`: generic `DynamicConfig` / `ConfigOptionDef` plumbing. Rarely modified.
- `src/libslic3r/Preset.hpp` / `Preset.cpp`: `Preset`, `PresetCollection`, inheritance resolution, serialization (system vs user), diff vs parent.
- `src/libslic3r/PresetBundle.hpp` / `PresetBundle.cpp`: load/save bundles, vendor profiles, filament library, project-embedded presets. Entry point `load_vendor_configs_from_json`.

### Pellet-specific code paths
- `src/libslic3r/GCode/PressureEqualizer.hpp` / `.cpp`: pellet ERS (Extrusion Rate Smoothing). Key fields `m_pellet_ers_mode`, `m_pellet_ers_travel_threshold`, `m_pellet_ers_ramp_profile`, `m_pellet_ers_deceleration_slope`, `m_pellet_ers_min_rate`. Mini-pass logic and ramp segments are tagged via `GCodeLine::pellet_ramp`.
- `src/libslic3r/PrintConfig.hpp` lines around `pellet_ers_*`, `pellet_modded_printer`, `use_active_pellet_feeding`, `extruder_rotation_volume`, `mixing_stepper_rotation_volume`.
- `resources/profiles/Ginger Additive/`: vendor profiles. Nozzle sizes 1.0 / 1.8 / 3.0 / 5.0 / 8.0 mm; process profiles 0.60 / 0.90 / 1.30 / 1.50 / 2.50 / 4.00 mm. All files share a single `version` that must be bumped together (see CI rules below).

### Settings UI
- `src/slic3r/GUI/Tab.hpp` / `Tab.cpp`: imperative construction of setting pages (Print / Filament / Printer). To add a UI line: `add_options_page` → `new_optgroup` → `append_single_option_line("opt_key")`.

- `src/slic3r/GUI/ParamsPanel.hpp` / `.cpp`: hosts the Print/Filament/Printer tabs in the main window.

### Slicing pipeline (read-only mental model)
- `src/libslic3r/Print.cpp` → `PrintObject.cpp` → `PrintObjectSlice.cpp` → `LayerRegion.cpp` → `PerimeterGenerator.cpp` → `GCode.cpp` (375k+ lines, the orchestrator) → `GCode/PressureEqualizer.cpp` (post-process pass).
- `src/libslic3r/GCode/CoolingBuffer.cpp`: layer-time estimation and cooling logic. Hosts the **volume-based cooling** formula `min_time = layer_height² × k` (toggle: `volume_based_cooling`, coefficient: `cooling_time_per_cross_section`). Parses `;HEIGHT:` tags from the G-code writer to support adaptive layer heights; tracks `max_layer_height` per extruder per layer. See `PerExtruderAdjustments::max_layer_height` and the slowdown branch in `calculate_layer_slowdown`.

### Multiline infill (Clipper2) — aligned to OrcaSlicer PR #11435 + #11765 + #10967
Pellet-relevant: `fill_multiline` prints infill as N parallel lines (max 10) instead of one — critical for large nozzles (1.0–8.0 mm) to avoid single-bead over-extrusion. Routing table:
- `deps_src/clipper2/`: vendored Clipper2 v1.5.2 (mirror of OrcaSlicer, incl. `clipper2_z`). Registered via `add_subdirectory` in `deps_src/CMakeLists.txt`, linked as `Clipper2` in `src/libslic3r/CMakeLists.txt` (`/WX` and `-Werror` stripped). Include root: `Clipper2Lib/include`.
- `src/libslic3r/Clipper2Utils.{hpp,cpp}`: Slic3r↔Clipper2 path/polygon conversion + boolean/offset helpers.
- `src/libslic3r/Fill/FillBase.cpp`: `multiline_fill(polylines, params, spacing)` (decl in `FillBase.hpp`) — the core offsetter using `ClipperOffset(JoinType::Round, EndType::Round)`, producing **closed rings** (callers MUST `intersection_pl` before `chain_or_connect_infill` or they crash). Carries `[multiline_fill]` `BOOST_LOG_TRIVIAL(debug/trace)` logs (gated, non-public builds). `connect_infill()` skips short connections when `multiline > 1` (#11765).
- `src/libslic3r/Fill/FillRectilinear.cpp`: `fill_surface_by_multilines()` (rewritten, Clipper2 path) and `fill_surface_trapezoidal(..., int Pattern_type)` (`0`=grid 45°, `1`=triangular 90°) — the non-crossing anti-over-extrusion pattern for Grid/Triangles when `multiline > 1`. Branch lives in `FillGrid::fill_surface` / `FillTriangles::fill_surface`.
- Pattern extensions: `FillConcentric.cpp`, `FillPlanePath.cpp` (Archimedean/Hilbert/Octagram), `Fill3DHoneycomb.cpp`, `FillHoneycomb.cpp`, `FillAdaptive.cpp`, `FillLightning.cpp`.
- **Density adjustment (#10967):** `FillAdaptive.cpp` (`adaptive_fill_line_spacing`, `* n_multiline`) and `Fill/Lightning/Generator.cpp` (`m_supporting_radius * n_multiline`, **only the infill `Generator(const PrintObject&...)` ctor**, not the BBS support ctor which divides by `density`). Without these, `multiline > 1` over-densifies adaptive/support cubic and lightning.
- UI gating: `src/slic3r/GUI/ConfigManipulation.cpp` `toggle_print_fff_options` → `have_multiline_infill_pattern` list + `if (have_infill) { toggle_field("fill_multiline", ...) }`. Max value `10` defined in `PrintConfig.cpp` (`fill_multiline`).

### Single-path infill (`connect_infill_polygons`) — Cura "Connect Infill Lines" port
Goal: make the inner wall + infill a single continuous extrusion path (no travel moves) for line-based patterns. Use with `fill_multiline=2` + `wall_loops=0`. Param key: `connect_infill_polygons` (bool, default false).
- **Cura cardinal points** (`CuraEngine/src/infill.cpp`): (1) **connect BEFORE multiply** — `connectLines()` joins single scanlines into one continuous path tracing the boundary, then `multiplyInfill()` offsets that path; (2) **vertex-by-vertex boundary walk, NO trimming** — guarantees full inner-wall coverage; (3) **UnionFind** prevents premature loop closure only.
- **GingerSlicer 3 blockers** (all in `FillBase.cpp` `connect_infill()`): (a) `mark_boundary_segments_touching_infill()` trims boundary segments near infill → gaps; (b) multiline-skip `if (params.multiline > 1 && arc.arc_length < spacing*multiline) continue;` → gaps; (c) `polyline_idx1 != polyline_idx2` blocks self-loop closure.
- **PIPELINE for multiline > 1 (final, 2026-06-11 — connect BEFORE multiply, Cura order):** in `fill_surface_by_multilines` and `fill_surface_trapezoidal` (FillRectilinear.cpp), when `connect_polygons && multiline > 1`: (1) clip the single-width centerlines to each island contracted by `(0.5*multiline + 0.15) * spacing` (the 0.15 margin keeps the widened band strictly inside the later `-0.5*spacing` clip — without it the band touches the clip boundary and gets nicked into fragments); (2) `connect_infill()` joins them into trail(s); (3) any closed trail is OPENED at its seam (a closed centerline would widen into two concentric loops); (4) `multiline_fill()` dilates the trails — the union outline comes back as ONE outer wall + the hole walls of the pockets the serpentine encloses (an open path that encloses cells produces holes!); (5) **`single_path_splice_loops()`** (FillBase.cpp, declared in FillBase.hpp) splices the walls into ONE closed loop: link the two nearest rings with two short segments at their closest approach, with the cuts STAGGERED by one extrusion width so the links land in the cut gaps instead of over extruded material; repeat until one ring. Result: **1 closed loop per island for ml=2 in every case incl. the narrow-strip soup** (bands of multiple trails fuse in the union) → zero travels AND free seam (ExtrusionLoop split_at the wall end). ml odd keeps the open centerline separate (splice skips open polylines). Covered by REQUIRE(size()==1 && is_closed && no retraced segments) tests.
- **Implementation (surgical, keeps multiply→connect order):** `create_boundary_infill_graph(..., bool skip_trimming)` skips the trimming when `params.connect_polygons`; the multiline-skip is gated with `! params.connect_polygons`. `FillParams::connect_polygons` (FillBase.hpp) ← `SurfaceFillParams::connect_polygons` (Fill.cpp, set from `region_config.connect_infill_polygons`, sparse only) → propagated to both `FillParams` construction sites in Fill.cpp. NOTE: with multiply-first, `multiline_fill()` makes racetrack rings, `intersection_pl` clips them to open polylines with endpoints on the boundary, THEN `connect_infill()` joins them — that's why the bypass works without a full reorder.
- **Connect algorithm (current, 2026-06-10, `FillBase.cpp` `connect_infill_single_path()`):** when `params.connect_polygons`, `connect_infill()` runs a **seam-stitch pre-pass** (fragments sharing an exact endpoint are re-joined: `multiline_fill()` ring seams can fall INSIDE the surface — trapezoidal rows do, rectilinear lines don't — and `intersection_pl` splits the ring there into two fragments meeting at an interior, unprojectable point), builds the untrimmed `BoundaryInfillGraph`, then branches into the dedicated **Eulerian-trail connector** and returns (the greedy anchor machinery below stays untouched for `connect_polygons=false`). The connector: vertices = fragment endpoints projected on the contours; **mandatory edges** = fragments; **optional edges** = boundary "gaps" between consecutive vertices along a contour, each usable ≤1× (extrusion along the inner wall — never twice, never a travel). Pass 1: greedy in-order matching per contour (Cura connectLines rule: never join two ends of the same chain; union-find). Pass 2 (repair): merge residual components with unused gaps, priority by odd-degree impact: loose-loose single gap (−2 odd) > loose-loose run over loose interiors (−2) > loose-matched (±0) > matched-matched (+2); a matched-matched gap **always exists between two components sharing a contour** (the component id must change at some boundary gap, and that gap can't be selected), so everything sharing a boundary merges — travels remain only between truly disconnected regions. Selection engine (final, 2026-06-11): with every gap available each contour is a RING (never a tree) and fragments are chords; a selection where each vertex keeps exactly one of its two gaps = an **alternating phase**; each phase boundary ("defect") = one odd vertex; **trails = Σ per component max(1, odd/2)** (travels = trails − 1) — this exact objective is `count_trails()`. Algorithm: start from the alternating phase per contour (greedy phase swap by trails), then **greedy sector flips** (toggle all gap states in a range; candidate boundaries = gaps adjacent to defects + deleted frontier gaps, capped at 48/contour) accepting flips that strictly reduce (trails, odds, length) lexicographically. KEY LESSON: do NOT use (components, odds) as the objective — splitting a component can REDUCE total trails when it splits the odd vertices too (a lexicographic comps-first greedy stalls at 5 trails on the narrow-strip case where trails-first reaches 3). **Pass 3b — Euler augmentation (CRITICAL correctness step, bug found 2026-06-10 on a real print):** the stack Hierholzer is only valid on Eulerian components; with >2 odd-degree vertices the vertex/edge association corrupts and materializes **retraced segments = double extrusion** (palindromic G-code moves). Fix: pair ALL remaining odd vertices per component with **virtual edges** (never extruded; the trail is split there = one travel each, the topological lower bound), paired greedily by EUCLIDEAN distance so each surviving travel is as short as possible; the circuit pieces split at virtual edges are re-joined across the arbitrary start vertex. Tests assert `require_no_retraced_segments` on every case — never weaken that. Pass 4: Hierholzer + materialization. Standalone fragments (closed rings inside the surface, unprojected endpoints) emitted verbatim. **Results (probed):** crossing Grid `multiline=1` → 1 CLOSED loop (zero wall→infill travel via ExtrusionLoop split_at); rectilinear/trapezoidal `multiline=2` square/L-shape → 1 OPEN path (connected all-even selection topologically impossible for racetrack rings); narrow-strip trapezoidal → 3 trails (2 short travels; best known for this topology). Failed approaches, do not retry naively: constructive in-order matching + repairs (tree-like selections, every release splits); max-independent-set "parity sculpting" from full selection (optimal released-sets are NOT independent sets); single-step odd walking (blocked when every taken gap is a bridge); comps-first lexicographic flips (see KEY LESSON above).
- **Seam / wall→infill travel:** `fill_surface_extrusion()` emits closed polylines as `ExtrusionLoop` when `params.connect_polygons` (`extrusion_entities_append_loops_and_paths`); `GCode::extrude_loop()` does `split_at(last_pos)` for non-perimeter loops, so a closed infill loop starts at the point nearest to where the wall ended → no wall→infill travel. Open trails keep one approach travel to the nearest of their two ends (nearest-endpoint chaining).
- **History of root causes fixed on the way (do not reintroduce):** (a) premature loop closure inside the length-sorted greedy loop made every multiline racetrack ring close onto itself → N isolated loops; closure is only valid as the very last step. (b) Length-sorted greedy matching is order-dependent: adjacent rings merging on opposite edges strand each other. (c) Boundary-only matching without repair strands tip groups with crossing patterns (Grid multiline=1) and narrow regions with trapezoidal rows (fragment soup) — the Eulerian formulation with gap repair subsumes all of these (crossings are irrelevant in the graph view). Reproducers in `tests/fff_print/test_fill.cpp` "Fill: connect_infill_polygons single path" (rectilinear ml2 square+L-shape, grid crossing ml1, grid trapezoidal ml2 square + narrow slanted strip — all REQUIRE exactly 1 path).
- **UI:** `Tab.cpp` `append_single_option_line("connect_infill_polygons")` after `fill_multiline`; `ConfigManipulation.cpp` `have_connectable_infill_pattern` (Rectilinear/AlignedRectilinear/Grid/Triangles/Stars/Cubic/QuarterCubic/ZigZag/CrossZag/LockedZag) gates `toggle_field`.

## Agent Workflow Tips
- **Localize before reading.** Use `code_search`/`grep_search` to find the 1–3 relevant files; never read large files (`Tab.cpp` 316k, `Plater.cpp` 631k, `GCode.cpp` 375k) end-to-end.
- **Prefer `.hpp` first** for orientation, then jump to `.cpp` definitions with `grep_search` on the symbol.
- **Bumping profile versions:** when changing any file under `resources/profiles/Ginger Additive/`, bump `version` in all 41 versioned JSON files together (see `scripts/check_profile_version_bump.py`).
- **Adding a parameter end-to-end** touches: `PrintConfig.hpp` (declaration) → `PrintConfig.cpp` (`def` with label/tooltip/range/mode) → `Preset.cpp` (`s_*_options` list for category) → `Tab.cpp` (`append_single_option_line`) → `ConfigManipulation.cpp` (toggle/visibility) → optional `resources/profiles/.../*.json` (defaults).
- **C++ symbol search:** if `compile_commands.json` exists, prefer LSP-driven tools over regex. Without it, fall back to `grep_search` on declarations.
- **clangd gotcha — config options are macro-generated.** Symbols declared inside `PRINT_CONFIG_CLASS_DEFINE(...)` (e.g. `adaptive_layer_height`, `pellet_ers_mode`, `layer_height`, all `((ConfigOption*, name))` entries in `PrintConfig.hpp`) are produced by Boost.PP-style macros that clangd cannot expand. `Shift+F12` / find-references returns nothing for these. Use `grep_search` directly with the option name as a literal string. This is not a bug in our setup — it is an intrinsic limit of LSP indexing on this macro pattern.
- **Domain glossary:** see `docs/ginger/GLOSSARY.md` for pellet-specific terms (ERS, ramp profile, deceleration slope, virtual retract, etc.).
- **Keep this file current.** Whenever you discover a non-obvious solution, gotcha, or root cause while working, add it here (or to `docs/ginger/GLOSSARY.md`) **in the same session** so the mistake is never repeated.

## Build & Environment gotchas (Windows)
- **Canonical incremental build:** `cmake --build build --target libslic3r --config Release --parallel 16` validates `src/libslic3r/` changes quickly (exit 0 = OK). GUI-only changes (`src/slic3r/GUI/*`, e.g. `ConfigManipulation.cpp`) live in `libslic3r_gui` and need the full `GingerSlicer` target to compile/link.
- **`edit` tool on duplicated code:** `Fill/Lightning/Generator.cpp` has TWO near-identical constructors (infill `Generator(const PrintObject&...)` vs BBS support `Generator(PrintObject*, ...)`). When editing, anchor on a UNIQUE line (e.g. `m_supporting_radius = ... * 100 / region_config.sparse_infill_density;` only exists in the infill ctor) or `old_string` will match multiple times and fail.
- **Unit tests on Windows:** the default build tree has `BUILD_TESTS=OFF`. Enable with `cmake -S . -B build -DBUILD_TESTS=ON`, then `cmake --build build --target fff_print_tests --config Release --parallel 16`; the exe lands in `build/tests/fff_print/Release/fff_print_tests.exe` (filter by test name, e.g. `fff_print_tests.exe "Fill: connect_infill_polygons*"`). Gotcha fixed 2026-06-10: `tests/*/CMakeLists.txt` called `orcaslicer_copy_dlls`, but the fork renamed the function to `gingerslicer_copy_dlls` (root `CMakeLists.txt:702`) — configure failed until the call sites were renamed.
- **MSVC tolerates trailing `\` in `//` comments** (ASCII-art line-continuation). It compiles on the Windows build even though GCC/Clang would warn with `-Wcomment`. `libslic3r` is NOT built with `/WX`, so such warnings don't break the build.
