# Repository Guidelines

## Project Structure & Module Organization
OrcaSlicer’s C++17 sources live in `src/`, split by feature modules and platform adapters. User assets, icons, and printer presets are in `resources/`; translations stay in `localization/`. CMake helpers reside in `cmake/`, and longer references in `doc/` and `SoftFever_doc/`. Automation scripts belong in `scripts/` and `tools/`. Treat everything in `deps/` and `deps_src/` as vendored snapshots—do not modify without mirroring upstream tags.

## Build, Test, and Development Commands
Use out-of-source builds:
- `cmake -S . -B build -DCMAKE_BUILD_TYPE=Release` configures dependencies and generates build files (Visual Studio generator on Windows).
- `cmake --build build --target GingerSlicer --config Release --parallel 16` is the canonical Windows build command. Output: `build/src/Release/GingerSlicer.dll` (loaded by `GingerSlicer_app_gui.exe`). Resources are symlinked into the build tree automatically.
Platform helpers such as `build_linux.sh`, `build_release_macos.sh`, and `build_release_vs2022.bat` wrap the same flow with toolchain flags. Use `build_release_macos.sh -sx` when reproducing macOS build issues, and `scripts/DockerBuild.sh` for reproducible container builds. Dependencies are pre-built in `deps/build/OrcaSlicer_dep/` (do not regenerate unless `deps_src/` changed).

## Coding Style & Naming Conventions
`.clang-format` enforces 4-space indents, a 140-column limit, aligned initializers, and brace wrapping for classes and functions. Run `clang-format -i <file>` before committing; the CMake `clang-format` target is available when LLVM tools are on your PATH. Prefer `CamelCase` for classes, `snake_case` for functions and locals, and `SCREAMING_CASE` for constants, matching conventions in `src/`. Keep headers self-contained and align include order with the IWYU pragmas.

## Testing Guidelines
**Automated tests are no longer supported in this fork (2026-07-30).** The `tests/` directory, Catch2, and the `BUILD_TESTS`/`ctest` CMake wiring were removed entirely. Do not autonomously reintroduce a `tests/` directory, Catch2, `ctest` integration, or any other automated test scaffolding — verify changes via headless slicing (see root `CLAUDE.md`) or manual GUI checks, and document manual printer validation or regression slicer checks in your PR instead.

## Commit & Pull Request Guidelines
The history favors concise, sentence-style subject lines with optional issue references, e.g., `Fix grid lines origin for multiple plates (#10724)`. Squash fixups locally before opening a PR. Complete `.github/pull_request_template.md`, include reproduction steps or screenshots for UI changes, and mention impacted presets or translations. Link issues via `Closes #NNNN` when applicable, and call out dependency bumps or profile migrations for maintainer review.

## Security & Configuration Tips
Follow `SECURITY.md` for vulnerability reporting. Keep API tokens and printer credentials out of tracked configs; use `sandboxes/` for experimental settings. When touching third-party code in `deps_src/`, record the upstream commit or release in your PR description and run the relevant platform build script to confirm integration.

Carries `[multiline_fill]` `BOOST_LOG_TRIVIAL(debug/trace)` logs (gated, non-public builds). `connect_infill()` skips short connections when `multiline > 1` (#11765).

### Single-path infill (`single_path_mode`) — Cura "Connect Infill Lines" port, taken further
Goal: make the inner wall + infill a single continuous extrusion path (no travel moves) for line-based patterns. Use with `fill_multiline=2` + `wall_loops=0`. Param key: `single_path_mode` (bool, default false; renamed 2026-06-13 from `connect_infill_polygons`, kept as a legacy alias in `PrintConfigDef::handle_legacy`). The internal `FillParams::connect_polygons` field keeps its name (not user-facing).
- **Cura cardinal points** (`CuraEngine/src/infill.cpp`): (1) **connect BEFORE multiply** — `connectLines()` joins single scanlines into one continuous path tracing the boundary, then `multiplyInfill()` offsets that path; (2) **vertex-by-vertex boundary walk, NO trimming** — guarantees full inner-wall coverage; (3) **UnionFind** prevents premature loop closure only.
- **GingerSlicer 3 blockers** (all in `FillBase.cpp` `connect_infill()`): (a) `mark_boundary_segments_touching_infill()` trims boundary segments near infill → gaps; (b) multiline-skip `if (params.multiline > 1 && arc.arc_length < spacing*multiline) continue;` → gaps; (c) `polyline_idx1 != polyline_idx2` blocks self-loop closure.
- **PIPELINE for multiline > 1 (final, 2026-06-11 — connect BEFORE multiply, Cura order):** in `fill_surface_by_multilines` and `fill_surface_trapezoidal` (FillRectilinear.cpp), when `connect_polygons && multiline > 1`: (1) clip the single-width centerlines to each island contracted by `(0.5*multiline + 0.15) * spacing` (the 0.15 margin keeps the widened band strictly inside the later `-0.5*spacing` clip — without it the band touches the clip boundary and gets nicked into fragments); (2) `connect_infill()` joins them into trail(s); (3) any closed trail is OPENED at its seam **only for EVEN multiline** (a closed centerline would widen into two concentric loops); for ODD multiline the centerline itself is extruded (`multiline_fill()` inserts it at offset 0) and must stay CLOSED so the splice merges it with the offset rings — fixed 2026-06-12 after a user report that seam realignment did not work with odd multiline; (4) `multiline_fill()` dilates the trails — the union outline comes back as ONE outer wall + the hole walls of the pockets the serpentine encloses (an open path that encloses cells produces holes!); (5) **`single_path_splice_loops()`** (FillBase.cpp, declared in FillBase.hpp) splices the walls into ONE closed loop: link the two nearest rings with two short segments at their closest approach, with the cuts STAGGERED by one extrusion width so the links land in the cut gaps instead of over extruded material; repeat until one ring; leftover rings are then ATTACHED to the closest open polyline as a detour (out-link and return-link share the junction point, ring cut staggered). **Splice gotcha (fixed 2026-06-12):** Clipper outlines have vertices only at corners/caps, so ALL closest-approach searches must project onto SEGMENTS, not compare vertices — a vertex-based link can come out tens of mm long running nearly parallel to an extruded wall (= overlap), and vertex-quantized stagger cuts can remove a long wall stretch. `walk_ring()` enters/exits at exact points; link-crossing is avoided by direction choice. Result: **1 closed loop per island for ml=2 in every case incl. the narrow-strip soup** (bands of multiple trails fuse in the union) → zero travels AND free seam (ExtrusionLoop split_at the wall end). ml odd: 1 closed loop when the centerline closes (grid trapezoidal), 1 OPEN path when it can't (rectilinear with an odd row count — parity makes a closed serpentine impossible; the ring is spliced into the open centerline as a detour). Covered by REQUIRE(size()==1 && is_closed && no retraced segments) tests.
- **Implementation (surgical, keeps multiply→connect order):** `create_boundary_infill_graph(..., bool skip_trimming)` skips the trimming when `params.connect_polygons`; the multiline-skip is gated with `! params.connect_polygons`. `FillParams::connect_polygons` (FillBase.hpp) ← `SurfaceFillParams::connect_polygons` (Fill.cpp, set from `region_config.single_path_mode`, sparse only) → propagated to both `FillParams` construction sites in Fill.cpp. NOTE: with multiply-first, `multiline_fill()` makes racetrack rings, `intersection_pl` clips them to open polylines with endpoints on the boundary, THEN `connect_infill()` joins them — that's why the bypass works without a full reorder.
- **Connect algorithm (current, 2026-06-10, `FillBase.cpp` `connect_infill_single_path()`):** when `params.connect_polygons`, `connect_infill()` runs a **seam-stitch pre-pass** (fragments sharing an exact endpoint are re-joined: `multiline_fill()` ring seams can fall INSIDE the surface — trapezoidal rows do, rectilinear lines don't — and `intersection_pl` splits the ring there into two fragments meeting at an interior, unprojectable point), builds the untrimmed `BoundaryInfillGraph`, then branches into the dedicated **Eulerian-trail connector** and returns (the greedy anchor machinery below stays untouched for `connect_polygons=false`). The connector: vertices = fragment endpoints projected on the contours; **mandatory edges** = fragments; **optional edges** = boundary "gaps" between consecutive vertices along a contour, each usable ≤1× (extrusion along the inner wall — never twice, never a travel). Pass 1: greedy in-order matching per contour (Cura connectLines rule: never join two ends of the same chain; union-find). Pass 2 (repair): merge residual components with unused gaps, priority by odd-degree impact: loose-loose single gap (−2 odd) > loose-loose run over loose interiors (−2) > loose-matched (±0) > matched-matched (+2); a matched-matched gap **always exists between two components sharing a contour** (the component id must change at some boundary gap, and that gap can't be selected), so everything sharing a boundary merges — travels remain only between truly disconnected regions. Selection engine (final, 2026-06-11): with every gap available each contour is a RING (never a tree) and fragments are chords; a selection where each vertex keeps exactly one of its two gaps = an **alternating phase**; each phase boundary ("defect") = one odd vertex; **trails = Σ per component max(1, odd/2)** (travels = trails − 1) — this exact objective is `count_trails()`. Algorithm: start from the alternating phase per contour (greedy phase swap by trails), then **greedy sector flips** (toggle all gap states in a range; candidate boundaries = gaps adjacent to defects + deleted frontier gaps, capped at 48/contour) accepting flips that strictly reduce (trails, odds, length) lexicographically. KEY LESSON: do NOT use (components, odds) as the objective — splitting a component can REDUCE total trails when it splits the odd vertices too (a lexicographic comps-first greedy stalls at 5 trails on the narrow-strip case where trails-first reaches 3). **Pass 3b — Euler augmentation (CRITICAL correctness step, bug found 2026-06-10 on a real print):** the stack Hierholzer is only valid on Eulerian components; with >2 odd-degree vertices the vertex/edge association corrupts and materializes **retraced segments = double extrusion** (palindromic G-code moves). Fix: pair ALL remaining odd vertices per component with **virtual edges** (never extruded; the trail is split there = one travel each, the topological lower bound), paired greedily by EUCLIDEAN distance so each surviving travel is as short as possible; the circuit pieces split at virtual edges are re-joined across the arbitrary start vertex. Tests assert `require_no_retraced_segments` on every case — never weaken that. Pass 4: Hierholzer + materialization. Standalone fragments (closed rings inside the surface, unprojected endpoints) emitted verbatim. **Results (probed):** crossing Grid `multiline=1` → 1 CLOSED loop (zero wall→infill travel via ExtrusionLoop split_at); rectilinear/trapezoidal `multiline=2` square/L-shape → 1 OPEN path (connected all-even selection topologically impossible for racetrack rings); narrow-strip trapezoidal → 3 trails (2 short travels; best known for this topology). Failed approaches, do not retry naively: constructive in-order matching + repairs (tree-like selections, every release splits); max-independent-set "parity sculpting" from full selection (optimal released-sets are NOT independent sets); single-step odd walking (blocked when every taken gap is a bridge); comps-first lexicographic flips (see KEY LESSON above).
- **Seam / wall→infill travel:** `fill_surface_extrusion()` emits closed polylines as `ExtrusionLoop` when `params.connect_polygons` (`extrusion_entities_append_loops_and_paths`); `GCode::extrude_loop()` does `split_at(last_pos)` for non-perimeter loops, so a closed infill loop starts at the point nearest to where the wall ended → no wall→infill travel. Open trails keep one approach travel to the nearest of their two ends (nearest-endpoint chaining).
- **Wall↔infill seam coordination + island ordering (GCode.cpp, 2026-06-12/13):** travel minimization has TWO coupled decisions — the ORDER features are visited, and each feature's ENTRY/EXIT (seam). The old code was greedy-backward only (`seam_position=nearest` → `SeamPlacer::pick_nearest_seam_point_index(last_pos)` looks at the *previous* position only) AND islands printed in fixed construction order (`//FIXME order islands?`), so every layer ended on one island and jumped back to island 0 — the SAME long diagonal repeated each layer (measured: 500 layer changes, ~119mm avg entry travel, top values 227.3→227.2→227.1… shrinking 0.08mm/layer as the part tapers = the fixed-order signature).
  - **Island ordering** (`process_layer`): replaced the fixed loop with `order_islands_tour(island_cand, last_pos(), island_entry)` — nearest-neighbour seed + 2-opt (capped at n≤256), seeded at the current nozzle position so it continues across the layer change. Each island is a DOWNSAMPLED point cloud (≤32 of its extrusion points via `collect_points`+stride), so the tour cost uses the real NEAREST APPROACH, not a centroid — a first attempt with centroids mis-ordered interlocking islands (two islands ~25mm apart printed non-consecutively; a gcode audit showed ~20% / 17.6m of inter-island travel was avoidable from that). `island_entry[i]` (the chosen entry point) feeds the look-ahead. GTSP/TSP-with-neighborhoods order heuristic; kills the repeated layer diagonal. Safe within one object instance (sequential PRINTING is handled at the instances loop, untouched).
  - **Seam selection per island (GCode.cpp `extrude_perimeters`, 2026-06-15):** `extrude_perimeters(..., next_island_target)` receives the NEXT island's entry point in the tour. The LAST perimeter's seam (`region.perimeters.back()`) is forced via `start_point` (→ `extrude_loop` `split_at`, bypasses SeamPlacer — cosmetic seam sacrificed for travel, pellet priority). TWO cases:
    - **Island WITH connectable infill:** `infill_connection_anchor(infills, from=last_pos(), to=next_island_target, out)` picks the infill connection point minimizing `dist(from,entry) + dist(exit,to)` — so the wall ends where the infill begins (0 wall→infill) AND the infill exit orients toward the next island. Connectable roles = `erInternalInfill`/`erSolidInfill`/`erTopSolidInfill`/`erBottomSurface` (NOT bridges/ironing). Open path: entry∈{end0,end1}, exit=other (also picks print DIRECTION); closed loop: entry==exit==seam. **A `no_sort` collection (monotonic solid/top/bottom) is treated as ONE ordered unit** — entry=`first_point()`, exit=`last_point()` — NOT recursed into (its emission order is fixed and `can_reverse()==false`, so the only valid entry is the sequence start; recursing would grab a mid-sequence line end and reintroduce a wall→infill travel).
    - **Wall-only island (no connectable infill — lightning's empty prongs, the bulk of its long inter-island travels):** **closest-point CHAIN** — the seam = the perimeter point with the smallest `dist(last_pos, p)`, i.e. CLOSEST to where the PREVIOUS island ended. "Position the next start by the previous end" → each island enters at its minimal curve-to-curve approach to the one before it. This alone took the real lightning part from 477 to 19 inter-island wall travels >100mm (matching grid). KEY: do NOT add a `+dist(p,next)` term here — that compromise pins/clusters the seam and barely helps (~3%); and do NOT apply the wall-only closest-point seam to infill islands (their departure is from the infill EXIT not the wall seam — it regressed grid 23.6→62.5m).
    - `wall_loops==0` needs nothing (`extrude_infill` already `split_at(last_pos)`).
  - **`can_reverse` gotcha (root cause of huge wall→infill jumps, fixed 2026-06-13):** `Fill.cpp` set `params.can_reverse=false` for `ipGrid` (the two crossing sweeps need a fixed line direction), which made `FillBase::fill_surface_extrusion` call `set_reverse()` on the entities. For `single_path_mode` the region is ONE connected OPEN path, and a non-reversible path can NOT be flipped by `chain_and_reorder_extrusion_entities` toward `m_last_pos` — so the path always started at its fixed `first_point`, NOT at the wall seam. The seam look-ahead then placed the wall seam at one end while the infill began at the other → 200-310mm travel straight across the island, then printing back. Fix: `pattern==ipGrid && !params.connect_polygons` keeps the connected path reversible so the chainer starts it at the wall seam (closed-loop infill is unaffected — `extrude_loop` `split_at` ignores `can_reverse`). Without this the whole seam-coordination silently inverts on open grid paths.
  - A FULL multi-step seam DP (optimal entry/exit for the whole layer at once) would need refactoring the streaming feature-by-feature emission into a two-pass (collect candidates → backward DP → emit); the one-step look-ahead captures most of the gain. General (non-connect) seam modes still go through the SeamPlacer unchanged — adding look-ahead there means touching `pick_nearest_seam_point_index`.
  - Validate per layer: `build\analyze_travels.ps1` (internal infill travels, want 0), `build\analyze_feature_travels.ps1` (wall→infill ~0; Sparse-infill→Outer-wall is the inter-island/layer hop, now much shorter), `build\find_spikes.ps1` (no doubled extrusion). History: wall→infill 80969mm→28507mm after seam coordination; layer-change entry travel 59446mm before island ordering.

Reversing a monotonic serpentine is still monotonic; a sortable collection is reversible by default (`is_reverse{true}`). Measured: guard solid internal travel 2921→1638mm (−44%), Outer wall max 288→87mm (cascade bonus); D1-P002 solid 8616→7357mm. Remaining solid travels are genuine inter-patch hops (disjoint solid surfaces, both ends far — an ordering/R5 floor). Gotchas: gap fill lands in the SAME eec (role `erGapFill`, excluded from the wall anchor); `is_flow_calib` re-forces no_sort after this line (kept); `link_max_length = 3×spacing` for density>80% (Fill.cpp ~1245) degrades long contour links to `LinkQuality::TooLong` which the emitter refuses — only relevant if emission breaks ever show up.
- **Wall rib connectors (2026-07-05, R1a + R2/R3 same day): `single_path_wall_ribs`** (bool, PrintRegionConfig, UI under Others > Special mode, enabled only with `single_path_mode`). Merges the closed wall loops of an island's region into ONE `ExtrusionLoop` by splicing rib connectors at the closest approach — the automated version of Davide's manual 0.05mm CAD slit welding a hole wall to the outer wall. Core = `src/libslic3r/WallRibs.{hpp,cpp}` `plan_wall_ribs()` (Prim/MST: repeatedly splice the loop closest to the growing walk; hole-to-hole ribs emerge naturally; `splice_wall_loops()` is the geometry-only wrapper for tests). **ARCHITECTURE (R2+R3, after Davide's GUI findings — infill/bottom extruded over the ribs, ribs printed on air): the plan is computed in `PrintObject::generate_wall_ribs()` (called at the END of `prepare_infill`, sequential bottom-up), NOT at G-code time**, because (a) the rib CORRIDORS (rib quad offset by 0.7×width) must be subtracted from the final `fill_surfaces` so sparse/solid/top/bottom never cross the rib beads (measured: zero sparse fragmentation side effect — one radial corridor cuts an annulus into a C, still connected), and (b) each rib must be ANCHORED to the previous layer's position (prev-anchor bias inside the Prim selection, validity = reprojected link ≤ optimal + 2×stagger) so the columns stack and are self-standing over sparse infill. Plan stored per layer in `Layer::wall_ribs` (`WallRibMerge{loop_keys, merged, corridors, anchors}`); `GCode::extrude_perimeters` only CONSUMES it, matching source loops by `first_point()` (the island regions reference the very same `ExtrusionLoop` objects; simplification/DP preserves endpoints) and requiring ALL keys of a merge to match (else warn + print loops separately). **Placement constraints (from Davide's first real reslice — 83/218mm ribs across the part in the void, giant corridors gutting the bottom fill, staircasing columns on the helical rim):** `WallRibParams` carries (1) `max_link_length` from the user param `single_path_wall_rib_max_length` (default 20mm) — Prim stops when the best remaining candidate exceeds it (best_dist only grows), distant holes stay unmerged and the seam chain covers them; (2) `obstacles` = ALL the island's loop polygons (multi-path ones included) — a link crossing any of them (interior hits only; endpoint contacts within one stagger excluded) rejects the merge; (3) `max_drift` = min(0.5×width, layer_height) per layer — an anchor whose reprojection moved farther ends the column instead of staircasing sideways; (4) corridor offset = exactly 0.5×width (flush: the fill fuses against the rib flanks, no gap strips on bottom/top). **(5) REAL SUPPORT CHECK (added after Davide's second reslice still showed air ribs):** `WallRibSupport{first_layer, prev_corridors, prev_walls, prev_solid}` — every candidate link is SAMPLED (every 0.5×stagger; ≤1 consecutive unsupported sample tolerated) against the previous layer's rib corridors ∪ wall loop centerlines (reach 0.55×width) ∪ SOLID fill surfaces; sparse infill is NOT support. Position selection per merge: (a) previous-layer anchor (drift-capped; over budget = the column ENDS, no relocation), else (b) optimal closest approach, else (c) SCAN ~48 positions around the loop projected onto the walk, nearest-first — actively finds a supported spot (e.g. over a new hole's bottom shells) instead of dropping. Verified on Davide's no-cuts D1-002: his pre-fix gcode had 37 wall segments ≥8mm in the air, the fixed build has ZERO. The air check (grid-hash of prev-layer extrusions, wall segments ≥8mm, unsupported run >~5mm) is asserted in the `[SinglePathRibs]` probe — never weaken it. TRADE: support-valid ribs are fewer (wall→wall travel goes up vs printing in air); the honest baseline. Design rules (Davide, binding): rib = TWO beads staggered by one line width so the flanks TOUCH (a gap would be a breaking point) but never share a centerline (extruding on itself clogs the nozzle); v1 merges only single-path loops with identical role/width/flow (overhang-split multi-path loops print separately); merged loop emitted at the position of its last member (preserves wall order + the last-wall→infill anchor). **Splice gotchas (bugs found by the unit tests, do not reintroduce):** (1) when the attach point is a CORNER, walking the stagger along the polygon turns onto an edge parallel to the link and the second link starts ON the first link's axis (beads overlap ~half the link) — the cut can sit BEFORE or AFTER the attach point on each side, so evaluate the 4 combinations and keep the one with the largest link-to-link separation; (2) same-direction loops need B reversed (anti-parallel tangents at closest approach) or the links cross; reversal remaps segment j → (2m−2−j) mod m. **Measured (D02 v02, plate with holes — 676 two-loop + 25 five/six-loop islands):** wall→wall travel 836/28.6m → 111/2.7m (−91%), wall extrusion +1.8% (the rib material), 0 retraced segments. **On single-loop-island parts the merge is a geometric no-op** — but check WHY the islands are single-loop: on D1-P002 it is because the 3mf models on H: already contain Davide's MANUAL CAD micro-cuts welding the holes to the outer wall (the feature's job, done by hand upstream); with the toggle those manual cuts become unnecessary. The residual 6.4m wall→wall there is INTER-island hops ~12mm — closing those needs a rib across VOID between islands = a new vertical web wall that changes the part; open design decision. ## Agent Workflow Tips
- **Localize before reading.** Use `code_search`/`grep_search` to find the 1–3 relevant files; never read large files (`Tab.cpp` 316k, `Plater.cpp` 631k, `GCode.cpp` 375k) end-to-end.
- **Prefer `.hpp` first** for orientation, then jump to `.cpp` definitions with `grep_search` on the symbol.
- **Bumping profile versions:** when changing any file under `resources/profiles/Ginger Additive/`, bump `version` in all 41 versioned JSON files together (see `scripts/check_profile_version_bump.py`).
- **Adding a parameter end-to-end** touches: `PrintConfig.hpp` (declaration) → `PrintConfig.cpp` (`def` with label/tooltip/range/mode) → `Preset.cpp` (`s_*_options` list for category) → `Tab.cpp` (`append_single_option_line`) → `ConfigManipulation.cpp` (toggle/visibility) → optional `resources/profiles/.../*.json` (defaults).
- **C++ symbol search:** if `compile_commands.json` exists, prefer LSP-driven tools over regex. Without it, fall back to `grep_search` on declarations.
- **clangd gotcha — config options are macro-generated.** Symbols declared inside `PRINT_CONFIG_CLASS_DEFINE(...)` (e.g. `adaptive_layer_height`, `pellet_ers_mode`, `layer_height`, all `((ConfigOption*, name))` entries in `PrintConfig.hpp`) are produced by Boost.PP-style macros that clangd cannot expand. `Shift+F12` / find-references returns nothing for these. Use `grep_search` directly with the option name as a literal string. This is not a bug in our setup — it is an intrinsic limit of LSP indexing on this macro pattern.
- **Domain glossary:** see `docs/ginger/GLOSSARY.md` for pellet-specific terms (ERS, ramp profile, deceleration slope, virtual retract, etc.).
- **Keep this file current.** Whenever you discover a non-obvious solution, gotcha, or root cause while working, add it here (or to `docs/ginger/GLOSSARY.md`) **in the same session** so the mistake is never repeated.

## Build & Environment gotchas (Windows)
- **Canonical incremental build:** `cmake --build build --target libslic3r --config Release --parallel 16` validates `src/libslic3r/` changes quickly (exit 0 = OK). GUI-only changes (`src/slic3r/GUI/*`, e.g. `ConfigManipulation.cpp`) live in `libslic3r_gui` and need the full `GingerSlicer` target to compile/link.
- **`edit` tool on duplicated code:** `Fill/Lightning/Generator.cpp` has TWO near-identical constructors (infill `Generator(const PrintObject&...)` vs BBS support `Generator(PrintObject*, ...)`). When editing, anchor on a UNIQUE line (e.g. `m_supporting_radius = ... * 100 / region_config.sparse_infill_density;` only exists in the infill ctor) or `old_string` will match multiple times and fail.
- **Unit tests on Windows:** the default build tree has `BUILD_TESTS=OFF`. Enable with `cmake -S . -B build -DBUILD_TESTS=ON`, then `cmake --build build --target fff_print_tests --config Release --parallel 16`; the exe lands in `build/tests/fff_print/Release/fff_print_tests.exe` (filter by test name, e.g. `fff_print_tests.exe "Fill: connect_infill_polygons*"`). Gotcha fixed 2026-06-10: `tests/*/CMakeLists.txt` called `orcaslicer_copy_dlls`, but the fork renamed the function to `gingerslicer_copy_dlls` (root `CMakeLists.txt:702`) — configure failed until the call sites were renamed.
- **MSVC tolerates trailing `\` in `//` comments** (ASCII-art line-continuation). It compiles on the Windows build even though GCC/Clang would warn with `-Wcomment`. `libslic3r` is NOT built with `/WX`, so such warnings don't break the build.
- **Headless full-slice tests were broken by harness bugs (fixed 2026-06-14), not by the slicer.** CI does NOT run the unit tests (commented out in workflows), so the `fff_print` full-slice tests bit-rotted. Root causes found & fixed: (1) `Test::gcode()` (test_data.cpp) exported to a bare `unique_path()` → `GCode::export_gcode` does `create_directory(parent_path()=="")` → throws "cannot find the path"; now anchored under `temp_directory_path()`. (2) **`Print::export_gcode()` unconditionally does `result->conflict_result = ...` — passing `nullptr` (as the tests did) is a guaranteed SIGSEGV**; `Test::gcode()` now passes a real `GCodeProcessorResult`. (3) data/resources dirs were never set → 3mf backup-load + g-code export `create_directory` failures; a Catch listener in `tests/catch_main.hpp` now calls `set_data_dir`/`set_temporary_dir`/`set_resources_dir`/`set_var_dir`/`set_local_dir` (mirrors `GingerSlicer.cpp` startup). (4) loading a project 3mf headless needs `LoadStrategy::LoadModel | LoadConfig | AddDefaultInstances` **and** a non-null `plate_data` — `AddDefaultInstances` alone (or `Default`) loads neither geometry nor config → `model.objects` empty. **`init_print` + `InfiniteBed` — NOT a bug to fix, it is the wrong tool for real-part tests.** `Slic3r::Test::init_print()` always runs `arrange_objects(InfiniteBed{})` which reports even one cube as off-bed → throws "Objects could not fit on the bed"; every `Test::slice()`-based case (PrintGCode, skirt_brim → the baseline SIGSEGV) fails/crashes there. The lesson (2026-06-14): `init_print` exists for SYNTHETIC test models — build a bare mesh in code, auto-place it on the bed, slice. For real GingerSlicer work that path is doubly wrong: (a) the synthetic config has gaps (empty `wipe_tower_x/y`, `printable_area`, …) that crash deep in `append_full_config`/`get_at`; (b) the arrange step is pure overhead. **A real `.3mf` already carries everything `init_print` would synthesize** — the G1 printer profile, the 1000×1000 bed, AND the object already positioned inside it. So arranging is a no-op at best and the `InfiniteBed` throw at worst. **Do NOT patch the arrange or the synthetic config; load the real 3mf instead** (`Model::read_from_file(path, &cfg, &ctx, LoadStrategy::LoadModel|LoadConfig|AddDefaultInstances, &plate_data, …)` then `print.apply(model, cfg)`), which skips arrange entirely. That is how the single_path guard runs and why it is robust. If a future test genuinely needs `Test::slice()` on a synthetic model, the real fix is to skip arrange when the bed is infinite (or to seed instance positions), but no current need justifies touching it.
- **single_path guard (`tests/fff_print/test_printgcode.cpp`, tag `[.][SinglePath]`):** loads a REAL Ginger 3mf (`tests/data/single_path_guard.3mf`, **gitignored — customer geometry, not committed**; the test self-skips if absent), slices headless, and asserts ZERO travel between two infill extrusions of one connected region + a loose wall→infill bound. Run with `fff_print_tests "[SinglePath]"`. Proven 2026-06-14: the real 500-layer part slices with 0 internal-infill travel; every SIGSEGV met along the way was harness infra (above), never the single_path code (all 500 layers `process_layer` enter+exit clean).
